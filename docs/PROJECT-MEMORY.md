A hand-off for anyone (or any future Claude session) who continues this work. It records what exists, why it is that way, how to run and deploy it, and what is still open. It holds **no secrets**. Last updated 2026-10-10.

## 2. Stack and where things live

- **Site:** plain HTML, CSS and JS, no framework. Pages are generated by `scripts/build_pages.py` from `src/*.html`, `src/*.json`. Run `python3 scripts/build_pages.py`, then `sh scripts/build_site.sh` (builds `dist-site`).
- **Admin:** `admin/` (ES modules), built by `sh scripts/build_admin.sh` into `dist-admin`.
- **Hosting:** Cloudflare Pages projects `mechanixpro-site` and `mechanixpro-admin` (Cloudflare account hello@mechanixpro.in; never touch the info@ziyam.in account). Domain `mechanixpro.in` (GoDaddy registration, Cloudflare DNS), admin at `admin.mechanixpro.in`.
- **Deploy:** `npx wrangler pages deploy dist-site --project-name mechanixpro-site --branch main` and the same for `dist-admin` / `mechanixpro-admin`. A push to GitHub `main` also triggers a Cloudflare Git build.
- **Backend:** Supabase project `mejdxsbpyscujpvbwvmg` (Postgres with RLS, Auth, Edge Functions in Deno, Storage). CLI is linked: `npx supabase db push --yes`, `npx supabase functions deploy <name> --use-api`, `npx supabase db query --linked "..."`. Migrations are in `supabase/migrations/` (latest `20261029000000_invoice_override.sql`).
- **Edge functions:** `submit-lead`, `confirm-booking`, `send-invoice`, `send-broadcast`, `unsubscribe`, `join-waitlist`, `track-booking`, `service-reminder`, `aisensy-lead`, `auth-email`, `whatsapp-webhook`, `follow-up`, `payment-link`, `razorpay-webhook`. Shared code in `supabase/functions/_shared/`.
- **Secrets** live only in Supabase function secrets (`npx supabase secrets set NAME=value`): the Resend key, Anthropic key, Razorpay, WhatsApp token, `CRON_SECRET`, `ALLOWED_ORIGINS`, `IP_SALT`, and similar. Never put them in the repo or in chat.
- **Public config** is `assets/js/config.js`: WhatsApp and call number, Supabase URL and anon key, Google tag IDs, Maps key, and switches. These are visible to every visitor by design.
- **Auth email:** login codes go through a Supabase "Send Email" hook to `auth-email`, then Resend (`docs/AUTH-EMAIL.md`).

## 3. Quality rules

- `npm test` runs every test (`node --test`). It stood at **481 passing** at the last run. Write the test first.
- The security policy in `_headers` forbids inline scripts. Use files and `addEventListener`. New third-party hosts must be added to the policy (it already allows Google Ads and Maps, Meta, Instagram embeds).
- Branch per change (`feat/…`, `fix/…`, `docs/…`), merge to `main`, then deploy. Commits end with the Co-Authored-By line.
- Keep prices consistent across `app.js` defaults, `build_pages.py`, the SQL seed and the FAQ. Edit prices in the admin, then run the sync.
- Only true claims. No fake urgency, discounts, ratings or reviews.

## 7. Lessons worth remembering

- The Resend tool available to Claude sessions is on a different account from the site's Resend (it does not have `mechanixpro.in` verified). Test emails must go through the admin button.
- `scripts/build_site.sh` runs `sync_prices.py`, which pulls live prices into `src/site.json` and the defaults in `assets/js/app.js`. Do not `git checkout` those files without re-running it.
- Google Ads' wizard fills in poor defaults (AI-written headlines, 100-mile location circles, Target ROAS, a full URL in the Final URL suffix). Always review every setting.
- Photos on the site are Wikimedia or stock images credited under their licences. Do not reuse them in ads.
- The Avatar Lab repo (smontlouis) is AGPL-3.0: do not copy its code into this site.
